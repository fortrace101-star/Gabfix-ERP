## Gabfix Laundry Front Office architecture
- Gabfix Laundry Front Office is a plain **Vite + React + TypeScript** SPA. `index.html` loads `src/main.tsx`, which mounts `src/App.tsx` (the root component).
- Routing is `react-router-dom` (`BrowserRouter`) inside `src/App.tsx`: `/` is the staff sign-in page (`src/pages/index.tsx`), `/dashboard/:section` is the protected workspace (`src/pages/dashboard.tsx` → `src/components/gabfix/laundry-dashboard.tsx`). There is no TanStack Router/Start/Query.
- Staff auth goes through the server API boundary `src/lib/api.ts` (`laundryApi.auth`: `login` / `refresh` / `logout` / `me`, canonical contract `POST /api/auth/login` → `{accessToken, refreshToken, user: {id, name, role, app_scope}}`; access + refresh tokens in `localStorage`). `src/components/ProtectedRoute.tsx` guards `/dashboard/:section` and preserves the attempted location for post-login redirect. Copy `.env.example` to `.env` and set `VITE_API_BASE_URL` + `VITE_APP_ID=laundry`.
- **No self sign-up:** staff accounts are created in the Admin Console (control-plane apex). There is no `/auth/sign-up` call anywhere; the server contract is frozen and no third-party endpoints exist.
- Use IndexedDB (`src/lib/offline-db.ts`, Dexie) only as an offline cache/outbox; the server API remains the permanent source of record.
- Authorization is scope-based: the JWT carries `{role, app_scope[]}` and the server enforces it on every mount; the client only receives the signed-in employee's own `role`/`app_scope`.
- Register the app-shell service worker only through `src/lib/pwa.ts`; preview and development must always unregister it. The worker is generated by `vite-plugin-pwa` at build time.
