## Gabfix Portal architecture
- Gabfix Portal is a plain **Vite + React + TypeScript** SPA. `index.html` loads `src/main.tsx`, which mounts `src/App.tsx` (the root component).
- Routing is `react-router-dom` (`BrowserRouter`) configured inside `src/App.tsx`; page components live in `src/pages/` (`index.tsx` = `/`, `auth.tsx` = `/auth`). There is no TanStack Router/Start/Query.
- There is **no BaaS client** — all backend access goes through the Gabfix server API, typed behind `src/lib/api.ts` (`portalApi`); employee auth tokens are held in `localStorage`. Copy `.env.example` to `.env` and set `VITE_API_BASE_URL` + `VITE_APP_ID=portal`.
- Auth uses the canonical server contract: `POST /api/auth/login` → `{accessToken, refreshToken, user: {id, name, role, app_scope}}`; no self sign-up (staff accounts are created in the Admin Console).
- Employee roles and app scopes stay enforced server-side (`employees.role`, `employees.app_scope[]`); the client only receives the signed-in employee's own `role`/`app_scope` via `portalApi.auth.me()`.
- The service worker (`dist/sw.js`) is generated by `vite-plugin-pwa` at build time. `src/lib/pwa.ts` registers it only in published production contexts; previews must unregister app-shell workers.
